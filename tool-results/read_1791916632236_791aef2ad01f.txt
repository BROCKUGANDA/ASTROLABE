    52→- Created 15 route files under `src/app/api/v1/`:
    53→  1. `ask/route.ts` (POST) — policy Q&A with 3-stage progress array + 400–700ms artificial retrieval latency. Maps PolicyAnswer.servedFrom ("extractive"|"live"|"cache") into the envelope's "live"|"cache"|"deterministic" space.
    54→  2. `policies/[slug]/route.ts` (GET) — returns `{docSlug,title,titleAr,sections[]}` filtered from `policies`. 404 with hint listing valid slugs.
    55→  3. `requests/route.ts` (GET + POST) — GET list with cursor pagination (max 50, cursor = `${openedAt}|${id}`), optional `?employeeId=` filter. POST creates with INTAKE_SCHEMAS validation, `resolveOwner`, idempotency cache (returns `servedFrom:"cache"` on retry), `E_NO_OWNER` 422 when owner null.
    56→  4. `requests/[id]/transition/route.ts` (POST) — uses `canTransition`; legal mutation returns updated request with `transition:{from,to}`; illegal returns `E_CONFLICT` 409; idempotent replay when `from===to` returns `servedFrom:"cache"`.
    57→  5. `pulse/route.ts` (POST) — `getConsent(employeeId,"pulse_capture")` gate; on rejection returns `E_CONSENT_REQUIRED` 412 with hint "Enable pulse capture in Me → Consent". On grant, pushes a new `PulseResponse` (id `PS-{ts36}`, commentRef derived when commentText present).
    58→  6. `consent/route.ts` (POST) — validates purpose against the 6 known purposes, appends to `consentRecords`, returns `{receiptId:"RC-{ts36}", consentRecordId, grantedAt, purpose, granted, version}`.
    59→  7. `me/data/route.ts` (GET) — PII-minimised SAR export: employee (no nationality/timezone), journey events, service requests, pulse responses (only if consent), consent records, empty auditEvents, synthetic viewLog (`Fatima Al-Mansouri · read_record · 2024-10-19T08:00:00Z · hrbp_review`), and `exportLink`.
    60→  8. `escalations/route.ts` (POST) — `E_UNPROCESSABLE` 422 if namedOwnerId missing/empty; verifies named owner exists; builds packet via `buildEscalationPacket` then overrides `namedOwner` with caller's choice (the builder defaults to HRBP).
    61→  9. `hrbp/queue/route.ts` (GET) — assesses every employee, sorts by band severity (blocked>friction>watch>steady) then lead-time-desc; optional `?band=` filter; each item has top 3 signals by weight + suggestedOwner (HRBP of record).
    62→  10. `manager/cohort/route.ts` (GET) — `?managerId=` filter; per employee returns ONLY `{employeeId, employeeName, journeyType, stage, dayInStage, aggregateCompletion, ownedSteps[]}`. `ownedSteps` filtered to `ownerGroup==="HR" && actor==="owner"`. NO signals, NO band, NO pulse, NO score — schema-level privacy boundary.
    63→  11. `insights/stalls/route.ts` (GET) — builds (stage × ownerGroup) grid from step defs; for each cell collects completed-step durations across all employees, computes median time-to-complete, breach rate, reassignment rate (from serviceRequests in that ownerGroup). k≥5 suppression: if unique contributors < 5 → `{suppressed:true, reason:"Not enough data to show safely (n<5)"}`.
    64→  12. `admin/replay/route.ts` (POST) — `{asOf, employeeIds?}`. Re-runs `assess(employee, asOf)` for each (or all if not specified). Surfaces unknown employeeIds as 404. Returns `{jobId:"replay-{ts36}", asOf, results:Assessment[]}` with `servedFrom:"deterministic"`.
    65→  13. `scenarios/route.ts` (GET) — returns the 5 seeded judge-mode scenarios (S1–S5) with id, employeeId, title, description.
    66→  14. `employees/route.ts` (GET) — lightweight list (id, ref, displayName, displayNameAr, journeyType, stage, location, role, team, startDate, effectiveDate, managerId, hrbpId) for the scenario switcher.
    67→  15. `journey/[id]/assessment/route.ts` (GET) — `?asOf=`. Returns `{assessment, trace}` so judge mode can render stage inference, signals fired/suppressed, fusion band, and next-best-step reasoning. `servedFrom:"deterministic"`.
    68→- Critical-rule adherence:
    69→  - Every response uses `success()` / `error()` from `@/lib/api/envelope`.
    70→  - `export const dynamic = "force-dynamic"` on every route.
    71→  - Query params via `req.nextUrl.searchParams`; bodies via `await req.json()` typed with `as` casts.
    72→  - No `Math.random()` for IDs — receipts/SR-IDs/pulse-IDs/consent-IDs/job-IDs all use `Date.now().toString(36)`. Math.random only used for the simulated retrieval latency in `/ask` (non-determinism of latency does not affect data).
    73→  - In-memory mutations done by pushing to the imported arrays directly (`serviceRequests`, `pulseResponses`, `consentRecords`) — prototype-only, as instructed.
